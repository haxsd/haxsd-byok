# 接入 ChatGPT 客户端中的 Codex

本模块面向 ChatGPT 桌面客户端中的本地 Codex 编程任务，以及使用同一配置的 Codex 客户端。原版 Codex 负责文件、终端、工具、审批、沙箱、上下文和多轮任务；haxsd byok 只转发模型推理。

普通 ChatGPT 云端聊天、语音和云端任务不在此接入范围内。

## 配置顺序

1. 在共享模型库添加 API 模型，选择与服务商一致的 Responses、Chat Completions 或 Anthropic 协议，填写实际上下文窗口。
2. 打开「Codex」页，选择可用模型和默认模型，启用网关并保存。
3. 确认本机网关已监听，再点击「应用到 Codex」。端口在监听只表示网关运行；应用配置之后客户端才会使用它。
4. 重新打开客户端或新建本地编程会话，选择配置的模型。
5. 在测试项目中让客户端修改文件、执行检查并读取结果，确认「调用」页出现来源为 Codex 的多轮记录。

模型的普通连通性测试不能代替第五步。模型是否会正确使用工具、遵守审批和完成长任务，仍取决于其实际能力。

## 配置归属

默认使用 `CODEX_HOME` 或用户目录下的 `.codex`。可以在页面指定绝对目录；该目录必须是目标客户端实际使用的目录。

应用仅修改 `config.toml` 中的模型路由、模型能力目录、上下文参数和托管搜索开关，并保存恢复收据。API Key 保留在本应用服务端；客户端配置只持有专用本地网关令牌。登录、`auth.json`、MCP、技能、hooks 和审批/沙箱设置保持原样。

第一版关闭官方托管搜索，不实现远程压缩、实时语音或 WebSocket。上下文压缩由 Codex 发起本地流程。桥接协议需要完整历史；无法表达的工具或远端历史引用会明确报错，不会退化成普通聊天。

## 修改与撤销

切换模型、端口或配置目录前，先点击「撤销接管」，再保存并重新应用。修改已应用模型的服务商配置后也需要撤销、重应用并新建会话，避免把原会话的推理状态发给另一个上游。

撤销会恢复受管字段并保留之后新增的无关配置。受管字段被其他软件或人工修改时，本应用拒绝覆盖，应先处理页面显示的冲突。

退出本应用会停止网关并撤销它应用的配置；再次使用时检查网关和配置状态。正在运行的旧会话可能仍缓存原路由，需新建会话。

## 故障检查

- 显示「未启用」：检查是否保存网关设置。
- 显示「待应用配置」：网关已运行，点击「应用到 Codex」。
- 显示「配置冲突」：目标目录已有其他 provider、profile 或受管字段的外部修改；保留原文件，不要强制覆盖。
- 客户端没有自配模型：确认配置目录正确，并重新打开客户端或新建会话。
- 提示托管工具不支持：确认已经应用最新配置；客户端额外开启的托管能力不属于本地工具桥接。
- 工具被审批或沙箱拒绝：在原版客户端检查权限；本应用不会绕过或放宽审批与沙箱。
- 调用中途断开：查看「调用」页的错误，区分上游拒绝、流截断、超时和用户取消。
