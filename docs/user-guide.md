# haxsd byok 用户指南

## 安装与升级

正式安装包在 [Releases](https://github.com/haxsd/haxsd-byok/releases/latest)。Windows x64 下载 `x64-setup.exe`；`.sig` 与 `latest.json` 是更新校验文件，不需要手动打开。

升级可在「系统设置 → 关于与更新 → 软件更新」完成，也可退出应用后运行新版安装包。安装器复用注册表中记录的安装位置，模型与统计保存在独立数据目录。

1.0.18 已修复大量旧数据导致启动一直「读取中」的问题。遇到该现象先确认版本，按 [故障排查](./troubleshooting.md) 处理，不要删除数据库或重复生成证书。

## 应用设置

系统设置按「常规」「网络」「记录与用量」「高级与诊断」「关于与更新」分类显示，顶部搜索可跨分类查找。

- 语言、主题与启动方式在「常规」；出网代理在「网络」。
- 保存请求与响应、模型定价及存储清理在「记录与用量」。完整记录可能包含对话和敏感内容，也会增加磁盘占用。
- 端口和日志信息在「高级与诊断」；端口编辑需要先打开开发者模式，修改后重启应用。
- Tab 补全与提交信息模型在「Cursor → 功能设置」；旧版模型配置从模型库顶部导入。
- 在设置分类之间切换或搜索时，尚未保存的表单内容会保留；只有点击保存才会应用复杂表单的改动。
- 关闭主窗口后，应用会隐藏到系统托盘，本地网关继续运行。要彻底退出，请在托盘菜单中选择「退出」。
- 「概览」的区间统计与最近调用每 2 秒自动刷新；过去一年的日历在回到窗口或手动刷新时更新。

## 添加模型

打开「模型 → 添加模型」，填写显示名称、协议、地址、API Key 和模型 ID。

- 点「获取模型」可从兼容接口读取模型列表。返回多个模型时，可以搜索并勾选需要的项批量添加；应用不提供「全选」，同一端点下已添加的模型会标记为「已存在」并禁用。
- OpenAI 兼容接口：填写服务商给的基础地址，通常包含 `/v1`，应用按协议追加路径。只有需要完整路径时才启用完整 URL 并填写具体接口地址。
- Chat Completions、Responses 和 Anthropic Messages 是不同协议，选择要匹配服务商。
- 模型 ID 使用服务商实际标识，显示名称可自定。
- 编程套餐 Key 与普通 API Key 可能使用不同地址，以套餐官方说明为准。

「测试」会调用配置的服务商，可能产生用量。成功只证明这次测试能完成；工具调用与长上下文等仍需在客户端验证。

401/403 检查凭据与权限；404 检查地址、路径和模型 ID；超时检查网络、系统代理与服务商状态。不要将含凭据的配置公开上传。

## 接入 Cursor

1. 准备一个配置正确的模型。
2. 在「Cursor」页初始化本地 CA，按提示完成信任。生成与信任是两个步骤。
3. 保存 Cursor 工作，再选择模型来源；确认框会说明这一步是否会结束正在运行的 Cursor 进程。
4. 手动重新打开 Cursor，选择模型并发起对话。
5. 检查 CA、模式、账号与「调用」页的实际记录。

### 三种模型来源

| 模式 | 模型列表 | 账号 | 请求去向 |
| --- | --- | --- | --- |
| 官方 | Cursor 自己的目录 | 完全由 Cursor 管理 | 全部直连官方 |
| 本地 | 只有模型库里的模型 | 没有账号时由本应用补一个本地账号 | 库里的模型走本机；不在库里的模型明确报错 |
| 混合 | 官方目录 + 追加模型库里的模型 | 需要你在 Cursor 里登录自己的账号 | 按模型 ID 分流：官方模型直连官方，库里的模型走本机 |

- 上下文压缩只作用于由本机模型回答的请求；官方模型的上下文由 Cursor 自己管理。
- 「本地」「混合」需要本机代理与本地 CA；「官方」不需要，也不写任何 Cursor 配置。
- 进出「官方」模式要写或撤代理配置，而 Cursor 只在启动时读它，所以这两种切换会结束 Cursor、需要你重新打开；「本地」与「混合」之间切换不需要重启。
- 「Cursor」页会显示官方模型目录的抓取状态。失败时官方模型会从列表里消失，原因（例如 401）显示在页面上。
- 「本地」模式只认识模型库里的模型：不在库里的模型会被明确拒绝，不会静默走官方——这是为了让"这次请求花谁的钱"始终可预期。

多智能体 / 后台子代理的收尾方式：父轮派出的后台子代理还没跑完时，父轮会保持"进行中"，
一直等到子代理结束、把它们的结果并进这一轮继续，而不是先收尾、之后再被唤醒；不会在固定
30 分钟后强制收尾。父轮只在子代理长时间没有任何活动（默认 45 分钟没有新的模型调用或工具
轮）或等待到达绝对上限（默认 6 小时）时才收尾。所以看到主对话在等子代理时不要去手动打断它；
中途你自己发消息也可以，那会开新的一轮，后台任务照常在跑。

### 上下文压缩（仅 Cursor 本机模型）

Cursor 原本使用自身的“上下文窗口 + 自动摘要”。开启本地或混合模式后，请求改由本机网关接管，Cursor 的官方摘要流程不再位于请求路径，因此由本应用执行压缩；官方模式仍由 Cursor 自己管理上下文。

同一 Cursor 会话接近模型上下文窗口时，自动压缩会把较早历史替换成一份交接摘要，并保留最近一部分轮次原文。摘要按工程交接编写：保留目标、已验证结果、进行中的工作、下一步、约束与决策、关键文件/命令/数值，以及未完成问题。

- 旧摘要不会再次交给模型改写，而是原样保留并明确标为历史，新压缩出的段追加在后面；当前状态与下一步以最新段为准。
- 自动压缩和手动 `/summarize` 发现摘要明显过短时，都会先按更严格的详细度要求重试一次；仍过短则追加最近用户/助手原文条目作为兜底。
- 活动摘要会随压缩次数增长，但总量受当前模型窗口约束；达到上限时会省略最旧的一段，并在摘要中指向压缩归档，避免旧摘要反过来挤掉当前对话。
- 「摘要输出上限」只是单次调用的最大输出，不是目标长度；实际目标会随被压缩的历史规模增长。
- 压缩记录中的摘要字符数、压掉的消息数与完整归档路径可在「调用」详情查看。归档包含压缩前历史，可用终端搜索找回摘要省略的细节。
- 压缩只能降低上下文长度，不能让任何模型在极长会话里始终保持短会话的推理质量。不同任务应尽量使用新会话；必须延续时，先在旧会话留下一份明确的交接说明。

CA 私钥应和 API Key 一样保管。更换证书后需重新打开 Cursor。

退出应用时会撤掉本应用写的代理配置，下次启动按当前模式重新应用。应用有退出清理与配置归属保护；崩溃后有残留配置时重新启动，让应用核对和清理。不要手工覆盖其他 BYOK 工具的配置。

### 出网方式与模型来源的搭配

「系统设置 → 网络 → 出网代理」只控制 BYOK 后端主动发起的 HTTP(S) 请求：模型上游、模型发现/测试、
图片下载、Cursor 官方/控制面转发、Devin 转发、插件网络与搜索抓取。它不控制客户端到本机
`127.0.0.1` 网关的连接，也不控制各客户端自己的云端功能。

| 出网方式 | 本机模型 | 官方 / 混合模式里的官方模型 |
| --- | --- | --- |
| 跟随系统代理（默认） | 按系统代理规则连接 | 取决于系统代理和当前网络 |
| 自定义 | 一律走指定地址，不按域名分流 | 需要指定代理能访问官方服务 |
| 直连 | 不使用代理 | 需要当前网络能直接访问官方服务 |

- 选择「直连」前，确认当前网络能访问所需的模型和官方服务；网络受限时可能需要代理。
- 「直连」同样作用于 Cursor 的官方与控制面请求，不会偷偷跟随系统代理。
- Cursor 经本机代理透传的第三方站点（例如扩展市场）不在这个设置里；Codex、Claude、Devin
  自己的账号、云任务等厂商功能也不在这个设置里。
- 「直连」只是不给本应用的请求设置 HTTP 代理；代理软件若开启 TUN/透明代理，流量仍会被
  系统网络层接管。
- 要按域名区分直连和代理，请选「跟随系统代理」，把分流交给代理软件的规则。
- 「跟随系统代理」读取的是静态 HTTP/HTTPS 系统代理；PAC/自动检测不支持，Clash 选「系统代理」即可。
- 系统代理暂时无法连接时，出网可能短暂改为直连，稍后自动重试；状态显示在「出网代理」里。

## 接入 Devin

各接入模块彼此独立，只用 Cursor 时无需开启 Devin。完整流程见 [Devin 手册](./devin-go-live.md)。

顺序：模型库 → Devin 默认模型与映射 → 保存并重启应用 → 写入接入配置 → 重启 Devin → 对话验证。

自动探测不到安装时，在「高级」里填写 Devin 安装目录或其中的 `extension.js`；设置文件路径也可手动指定。

## 接入 ChatGPT 客户端中的 Codex

「Codex」页通过本机网关替换本地编程任务的模型推理，保留原版 Codex 的工具、终端、审批、沙箱和任务循环。支持共享模型库中的 Responses、Chat Completions 与 Anthropic API 模型。

顺序：模型库（填写真实上下文窗口）→ Codex 选择模型并保存 → 应用配置 → 客户端新建编程会话 → 修改文件和执行检查 → 查看 Codex 调用记录。完整说明见 [Codex 手册](./codex-go-live.md)。普通 ChatGPT 云端聊天不属于此接入范围。

## 接入 Claude

「Claude」页由一个本机 Anthropic Messages 网关和两个客户端适配组成：Claude Code CLI 与 Claude Desktop。网关默认端口 `43121`，只监听 `127.0.0.1`，提供 `/v1/messages`、`/v1/messages/count_tokens` 与 `/v1/models`；凭据是本应用自己的 Bearer 令牌，走这条路径不需要在 Claude Code 里登录 Anthropic 账号。

顺序：模型库 → 默认模型与家族别名 → 启用网关并保存 → 按客户端应用接管 → 重新打开客户端发起对话 → 在「调用」页查看记录。

### 网关与模型映射

- 网关默认不启用；启用前必须先选默认模型；关闭时端口不监听。
- 网关先按模型哈希、再按 `claude-<哈希>` 发现 ID、再按请求里的 `sonnet` / `opus` / `haiku` 家族名解析，最后回落到默认模型。未知模型不会报错：Claude Code 会发送它自带的版本化 ID，不要求你逐个登记。
- Sonnet / Opus / Haiku 三个别名可以留空，留空时回落到默认模型；默认模型接住所有无法识别的请求。
- `/v1/models` 只列出默认模型与三个别名（按哈希去重），不是整个模型库；列表里的 ID 是 `claude-<哈希>`，显示名来自模型库。
- 保存后立即按新端口监听；端口被本应用其它网关或别的程序占用时，保存会被拒绝，不会留下「已保存、未监听」的状态。
- 「网关地址」和「访问令牌」可在页面上复制；「复制环境变量」给出可直接在终端使用的 `KEY=value` 列表。

### Claude Code CLI

「Claude Code CLI」标签页写 `%USERPROFILE%\.claude\settings.json`；设置了 `CLAUDE_CONFIG_DIR` 时写该目录下的同名文件。只改 `env` 里的这些键：

- `ANTHROPIC_BASE_URL`（不带 `/v1`）
- `ANTHROPIC_AUTH_TOKEN`
- `CLAUDE_CODE_ATTRIBUTION_HEADER=0`
- 选中别名时的 `ANTHROPIC_DEFAULT_{SONNET,OPUS,HAIKU}_MODEL` 与对应的 `_NAME`

- 没有检测到 Claude Code（配置目录、`settings.json` 与 `claude` 可执行文件都不存在）时状态是「未检测到」，应用按钮不可用；先安装并运行一次 Claude Code。配置目录或 CLI 已存在、只是还没有 `settings.json` 时，应用会新建该文件。
- 文件已存在时，首次写入前留整份备份 `settings.json.haxsd-byok.bak`，之后的应用不会覆盖它；文件原本不存在时没有可备份的内容，撤销后留下的是去掉这些键之后的 `settings.json`。
- 应用后需要重新打开 Claude Code；已经运行的会话不会切到网关。
- 撤销只移除上述键并还原接管前的值；你后来改过的值会保留并在页面上报告，不会被静默覆盖。
- 以下情况会阻断并显示在「冲突与阻断」里：`settings.json` 不是合法 JSON；`apiKeyHelper` 有值；`env` 里已有不是本应用写入的 `ANTHROPIC_BASE_URL`；已有 `ANTHROPIC_API_KEY`，或显式开启（值不是 `false`）了 `CLAUDE_CODE_USE_BEDROCK`、`CLAUDE_CODE_USE_VERTEX`、`CLAUDE_CODE_USE_FOUNDRY`。
- 存在系统级托管（`managed-settings.json`、它的 `managed-settings.d` 目录里的文件，或注册表 `SOFTWARE\Policies\ClaudeCode`）时状态为「受管配置」，本应用不会改写它。
- 用户环境变量里的同名键只提示、不阻断：从本应用之外启动的 Claude Code 可能仍读到旧值。

### Claude Desktop

「Claude Desktop」标签页写 `%LOCALAPPDATA%\Claude-3p\configLibrary`：`_meta.json` 是条目表与当前 `appliedId`，每个条目是一个 `<uuid>.json` profile。本应用只追加或更新自己的条目，其它条目、profile 与未知字段原样保留。

- 先完全退出 Claude Desktop（从托盘退出或结束进程，只关窗口不算）再应用或撤销；它运行时页面只给提示，服务端会拒绝写入。
- 模型列表至少选一个，第一项是默认模型，顺序会写进客户端的模型列表；可以上移、下移、移除，模型来自共享模型库。
- 应用后重新打开 Claude Desktop。首次写入前会给现有的 `_meta.json` 留一份 `_meta.json.haxsd-byok.bak`。撤销会删除本应用的条目与 profile，并把 `appliedId` 还原为接管前的值；你之后改过 profile 时不会删除，只在页面上报告。
- 状态为「机器策略」（`HKLM\SOFTWARE\Policies\Claude`）时页面只显示手工配置引导：本应用不写 profile，也不写任何组策略。
- `HKCU\SOFTWARE\Policies\Claude` 有策略时同样只给引导；本应用不写组策略，需要先移除该策略才能改回 profile 接管。
- 手工引导在 Claude Desktop 里打开 Developer → Configure Third-Party Inference，逐项填写：Gateway base URL、Static API key（本机网关令牌）、Auth 选 Bearer、模型列表（`claude-<哈希>` 与显示名）、Model discovery 选 Off、Allow Code 选 On。页面上的复制按钮只复制对应字段，不会替你在客户端里保存。

### 接管状态与令牌轮换

- 网关由本应用进程提供。正常退出应用（从托盘选择退出）会撤销 CLI 接管；Claude Desktop 未运行时也撤销 Desktop 接管，正在运行时服务端无法改写它的 profile，接管保留到下次启动。下次启动后重新应用接管。
- 改端口、轮换令牌或改模型映射后，页面状态可能显示「配置已过期」：客户端里仍是旧值，重新应用接管即可；Desktop 还要先完全退出。
- 「重新生成」会立即让旧令牌失效。Claude Desktop 正在运行或已接管时，先完全退出 Claude Desktop，已接管再撤销 Desktop 接管，然后轮换；CLI 已接管时，应用会自动把新令牌写回 `settings.json`。
- 强制结束或崩溃不会执行退出清理：接管文件会保留，下次启动网关会重新监听同一端口，通常可以直接继续使用；改过端口、令牌或模型映射时按「配置已过期」重新应用。

### 订阅账号（可选）

在「插件配置」页使用内置插件 `claude-code-auth`，它把 Claude Pro/Max 订阅的 OAuth 授权当作模型来源；登录后模型出现在模型库，可以像普通模型一样绑给 Claude 网关。完整说明、已核实事实和排查表见 [Claude 订阅账号接入](./claude-account.md)。

- 优先使用 Anthropic API Key：订阅 OAuth 用于第三方客户端可能违反 Anthropic 的消费者条款，可能被限流或封号，上游也可能直接拒绝。
- 插件不伪装 Claude Code 的 User-Agent、计费头或设备指纹；登录成功不代表调用一定成功。
- 凭证明文保存在本机数据库，能读取数据目录的人可以拿走。
- 无法保证平台不处罚；需要稳定、可预期的接入时用 API Key。

### 常见问题

| 现象 | 处理 |
| --- | --- |
| Claude Code 提示未登录 | 走本机网关不需要登录 Anthropic 账号，凭据是 `ANTHROPIC_AUTH_TOKEN`。确认已应用接管，并且 Claude Code 是在应用之后重新打开的；配置被别的工具改写时重新应用一次接管 |
| 订阅账号登录失败或 401 / 403 | 在插件账号里刷新令牌，仍失败就删除账号重新登录；`400` 且含 `third-party` / `extra usage` 表示上游不接受这种用法，改用 API Key |
| 授权时报回调端口被占用 | 回调地址是 `http://localhost:54545/callback`；关掉占用 54545 的进程（例如另一个登录窗口）再重试 |
| 请求打到了别的模型 | 未知模型会回落到默认模型，这是设计行为；检查默认模型与三个家族别名是否选了想要的模型 |
| 保存网关时提示端口被占用 | 换一个端口再保存；保存失败时原来的监听与设置保持不变，不会出现「已保存、未监听」 |
| `/model` 里显示的是哈希 | 映射写入的是模型库哈希；支持 `ANTHROPIC_DEFAULT_*_NAME` 的版本会显示显示名，不支持的版本直接显示哈希，这是预期行为 |
| 应用了 Desktop 接管但不生效 | 先完全退出 Claude Desktop（含托盘）再启动；仍不生效就看「配置来源」与冲突条目，受管状态只能手工配置 |
| 改了端口、令牌或模型映射后连不上 | 状态可能显示「配置已过期」，重新应用接管；Desktop 还要先完全退出。轮换令牌时 Desktop 正在运行或已接管要先退出/撤销，CLI 会自动同步新令牌 |
| 退出应用后 Claude Code / Desktop 连不上 | 正常退出会撤销 CLI 接管，Desktop 未运行时也撤销；Desktop 运行中则保留。下次启动后重新应用接管。强制结束或崩溃后接管文件保留，下次启动通常可以直接继续使用 |

## 调用与价值估算

「调用」页显示结果、耗时和 Token。详情记录受系统设置影响，并非永久保存。

「价值估算」按每个模型的单价与实际用量分别计算，再汇总已定价模型。请在「系统设置 → 记录与用量 → 模型定价」填写实际渠道单价，选择全时段固定价格或高峰/低谷两套价格；未定价模型的用量不计入金额。

分时计算按小时用量进行；当前高峰规则为 UTC 工作日 `01:00–04:00`、`06:00–10:00`，这是应用内规则，不是对服务商未来定价的承诺。

简体中文使用人民币、英文使用美元，两套单价分别保存。修改单价会重新估算历史用量；费用估算不是服务商账单。

## 记录与数据保留

当前实现：

| 数据 | 行为 |
| --- | --- |
| 模型配置与设置 | 持久保存，直到用户修改或删除 |
| 累计调用与 Token 统计 | 清理详情时保留 |
| 已结束调用的请求/响应详情、追踪附件 | 超过 3 天后可清理 |
| 无活动运行的闲置会话状态 | 超过 3 天后可清理 |
| 没有会话或追踪引用的内容块 | 最近读写 1 小时后可分批清理；保留会话引用的内容不按此规则删除 |

清理在没有活动会话传输时执行。SQLite 复用删除后留下的空闲页，所以文件不会随每次清理立即变小；文件大小不能单独代表有效数据量。

## 备份与恢复

默认目录 `%USERPROFILE%\.haxsd-byok-devin-v3`，数据库为 `haxsd-byok.db`。程序与数据目录是两回事。

正常退出并确认应用进程结束，再复制完整数据目录到安全位置。运行时不要只复制主数据库，SQLite WAL 可能含未合并的数据。备份包含凭据和证书材料，不要公开上传。

恢复前同样退出，保留当前副本，再恢复备份。优先在相同版本恢复并验证；不要直接降级程序并打开新版迁移后的数据库。
