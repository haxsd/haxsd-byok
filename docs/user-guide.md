# haxsd byok 用户指南

## 安装与升级

正式安装包在 [Releases](https://github.com/haxsd/haxsd-byok/releases/latest)。Windows x64 下载 `x64-setup.exe`；`.sig` 与 `latest.json` 是更新校验文件，不需要手动打开。

升级可在「系统设置 → 软件更新」完成，也可退出应用后运行新版安装包。安装器复用注册表中记录的安装位置，模型与统计保存在独立数据目录。

1.0.18 已修复大量旧数据导致启动一直「读取中」的问题。遇到该现象先确认版本，按 [故障排查](./troubleshooting.md) 处理，不要删除数据库或重复生成证书。

## 添加模型

打开「模型 → 添加模型」，填写显示名称、协议、地址、API Key 和模型 ID。

- OpenAI 兼容接口：填写服务商给的基础地址，通常包含 `/v1`，应用按协议追加路径。只有需要完整路径时才启用完整 URL 并填写具体接口地址。
- Chat Completions、Responses 和 Anthropic Messages 是不同协议，选择要匹配服务商。
- 模型 ID 使用服务商实际标识，显示名称可自定。
- 编程套餐 Key 与普通 API Key 可能使用不同地址，以套餐官方说明为准。

「测试」会调用配置的服务商，可能产生用量。成功只证明这次测试能完成；工具调用与长上下文等仍需在客户端验证。

401/403 检查凭据与权限；404 检查地址、路径和模型 ID；超时检查网络、系统代理与服务商状态。不要将含凭据的配置公开上传。

## 接入 Cursor

1. 准备一个配置正确的模型。
2. 在「Cursor」页初始化本地 CA，按提示完成信任。生成与信任是两个步骤。
3. 保存 Cursor 工作，再选择模型来源；确认框会说明这一步是否会结束正在运行的 Cursor 进程。
4. 手动重新打开 Cursor，选择模型并发起对话。
5. 检查 CA、模式、账号与「调用」页的实际记录。

### 三种模型来源

| 模式 | 模型列表 | 账号 | 请求去向 |
| --- | --- | --- | --- |
| 官方 | Cursor 自己的目录 | 完全由 Cursor 管理 | 全部直连官方 |
| 本地 | 只有模型库里的模型 | 没有账号时由本应用补一个本地账号 | 库里的模型走本机；不在库里的模型明确报错 |
| 混合 | 官方目录 + 追加模型库里的模型 | 需要你在 Cursor 里登录自己的账号 | 按模型 ID 分流：官方模型直连官方，库里的模型走本机 |

- 压窗只作用于由本机模型回答的请求；官方模型的上下文由 Cursor 自己管理。
- 「本地」「混合」需要本机代理与本地 CA；「官方」不需要，也不写任何 Cursor 配置。
- 进出「官方」模式要写或撤代理配置，而 Cursor 只在启动时读它，所以这两种切换会结束 Cursor、需要你重新打开；「本地」与「混合」之间切换不需要重启。
- 「Cursor」页会显示官方模型目录的抓取状态。失败时官方模型会从列表里消失，原因（例如 401）显示在页面上。
- 「本地」模式只认识模型库里的模型：不在库里的模型会被明确拒绝，不会静默走官方——这是为了让"这次请求花谁的钱"始终可预期。

多智能体 / 后台子代理的收尾方式：父轮派出的后台子代理还没跑完时，父轮会保持"进行中"，
等它们回来再把结果并进这一轮继续，而不是先收尾、之后再被唤醒。所以看到主对话在等子代理时
不要去手动打断它；中途你自己发消息也可以，那会开新的一轮，后台任务照常在跑。

CA 私钥应和 API Key 一样保管。更换证书后需重新打开 Cursor。

退出应用时会撤掉本应用写的代理配置，下次启动按当前模式重新应用。应用有退出清理与配置归属保护；崩溃后有残留配置时重新启动，让应用核对和清理。不要手工覆盖其他 BYOK 工具的配置。

### 出网方式与模型来源的搭配

设置页的「代理设置」对本应用的所有外部请求都生效，包括转发给官方的那部分：

| 出网方式 | 本机模型 | 官方 / 混合模式里的官方模型 |
| --- | --- | --- |
| 跟随系统代理（默认） | 按系统代理规则走，国内服务通常直连 | 能出境 |
| 自定义 | 一律走你填的地址；**不按域名分流**，填境外节点会让国内模型的请求也绕出去 | 能出境（前提是该地址能出境） |
| 直连 | 最快、最稳 | **连不上**——官方模型需要访问境外 |

- 用官方或混合模式时选「直连」，官方模型会失败；页面会在出网方式旁给出这条提示。
- 只想用本机（国内）模型时，「直连」是最省事的选择。
- 要"国内直连、境外走代理"同时成立，请选「跟随系统代理」，把分流交给代理软件的规则——本应用不做按域名分流。
- 系统代理那一跳连不上时（例如代理软件正在更新），出网会短暂改为直连，几分钟后自动回试；状态显示在「代理设置」里。

## 接入 Devin

Cursor 与 Devin 是并列模块，只用 Cursor 时无需开启 Devin。完整流程见 [Devin 手册](./devin-go-live.md)。

顺序：模型库 → Devin 映射与网关 → 保存并重启应用 → 宿主检查与补丁 → 重启 Devin → 对话验证。

## 调用与价值估算

「调用」页显示结果、耗时和 Token。详情记录受系统设置影响，并非永久保存。

「价值估算」使用记录的用量和应用内单价。可设置固定价格，或高峰/低谷两套参考价格。分时计算按小时用量计算；当前高峰规则为 UTC 工作日 `01:00–04:00`、`06:00–10:00`，这是应用内规则，不是对服务商未来定价的承诺。

简体中文使用人民币、英文使用美元，两套单价分别保存。不同模型价格可能不同，这个指标按统一参考价格计算，不能代替多服务商精确账单。

## 记录与数据保留

当前实现：

| 数据 | 行为 |
| --- | --- |
| 模型配置与设置 | 持久保存，直到用户修改或删除 |
| 累计调用与 Token 统计 | 清理详情时保留 |
| 已结束调用的请求/响应详情、追踪附件 | 超过 3 天后可清理 |
| 无活动运行的闲置会话状态 | 超过 3 天后可清理 |
| 没有会话或追踪引用的内容块 | 最近读写 1 小时后可分批清理；保留会话引用的内容不按此规则删除 |

清理在没有活动会话传输时执行。SQLite 复用删除后留下的空闲页，所以文件不会随每次清理立即变小；文件大小不能单独代表有效数据量。

## 备份与恢复

默认目录 `%USERPROFILE%\.haxsd-byok-devin-v3`，数据库为 `haxsd-byok.db`。程序与数据目录是两回事。

正常退出并确认应用进程结束，再复制完整数据目录到安全位置。运行时不要只复制主数据库，SQLite WAL 可能含未合并的数据。备份包含凭据和证书材料，不要公开上传。

恢复前同样退出，保留当前副本，再恢复备份。优先在相同版本恢复并验证；不要直接降级程序并打开新版迁移后的数据库。

## 插件与反馈

按「插件配置」页提示初始化运行环境并配置账号，只安装信任的插件。

提交 [Issue](https://github.com/haxsd/haxsd-byok/issues) 时提供应用、系统与客户端版本，重现步骤和脱敏错误信息，不要上传 Key、CA 私钥或完整数据库。[开发指南](./development.md)另列构建与验证步骤。
