# Devin 上手与恢复

当前产品操作流程如下。

## 1. 准备应用与模型

从 [Releases](https://github.com/haxsd/haxsd-byok/releases/latest) 安装，在「模型」页添加并测试一个模型。地址、Key、模型 ID 和协议需匹配服务商；测试是真实请求。

## 2. 配置映射与网关

打开「Devin」页：

1. 点「添加自选模型」，选择模型库中的模型：它会以模型库名称直接出现在 Devin 原生选择器；已有官方目录保留。需要替换已有 Devin 模型时，点「添加 Devin 模型」并从列表选择模型，不要编造 UID。
2. 选择一个已启用映射作为默认模型，Devin 打开时默认选中它。
3. 启用网关。
4. 如需备用模型，在「高级」中添加候选路由并显式选择当前路由；失败不会自动换路由。
5. 保存并重启 **haxsd byok**，确认网关监听状态。

仅监听 `127.0.0.1`：

| 默认端口 | 用途 |
| --- | --- |
| `43110` | 模型目录与分配 |
| `43111` | 推理流 |
| `43112` | Devin 本机 API |

令牌可选。设置后客户端请求需带 `x-devin-router-token` 或 `Authorization: Bearer <令牌>`；填写前确认客户端能够发送该值。

## 3. 写入接入配置

如果自动探测不到 Devin，展开「高级」：在「Devin 安装目录」填安装目录或其中的 `extension.js`，在「Devin 设置文件路径」填数据目录或 `User\settings.json`；留空则自动探测。

先保存工作并**完全退出 Devin**（包括托盘和后台进程）。回到「Devin」页，检查接入状态，然后点击「写入接入配置」。

打包版 Devin 默认只在开发扩展存在时读取两个端点设置；本产品按端点设置函数的结构与上下文唯一识别并放开这一处读取，不锁定某个版本号或预置扩展哈希，不改模型协议，也不写入任何模型地址。写入前会同时校验设置文件和 `extension.js`，给两边各留一份 SHA-256 备份与恢复收据。

「连接到 Devin」卡片显示接入状态，设置路径、扩展文件、端口与兼容补丁可在「技术详情」查看。配置已写入不等于网关正在运行，还需确认网关监听与真实调用。无法唯一识别该端点设置结构、补丁状态不一致或现有备份与收据冲突时会拒绝写入，不要强行覆盖。

重新打开 Devin。端口变化需保存、重启 haxsd byok、重新写入接入配置，再重启 Devin。

## 4. 验证请求

在 Devin 发起对话，回到「调用」页确认模型、结果与用量。端口监听只证明网关启动，补丁状态只证明文件配置完成，仍需真实请求验证。

无记录时依次检查：客户端是否重启、UID 是否有启用映射、选中模型是否存在、服务地址与兼容补丁是否都写入且端口一致、令牌是否匹配。

实际验证中，已有会话的本机模型请求可以正常回答；新会话仍可能被 Devin 官方提示“You ran out of free credits”。账号额度、套餐、登录和新会话资格都由官方服务控制，本产品不会伪造或绕过。没有可用额度时，换用仍有官方访问资格的账号，或继续使用已创建且仍可发送消息的会话。

## 5. 停用与恢复

退出 Devin，使用「恢复设置」还原服务地址和扩展读取开关，再关闭网关、保存并重启 haxsd byok，最后打开 Devin。

恢复会校验当前文件和备份。客户端升级或其他工具改过文件后可能拒绝恢复，此时用客户端自身的修复或重装流程，不要用旧备份覆盖新版本。

正常退出 haxsd byok 会保留 Devin 接入配置，但网关会停止；使用本机模型时需让 haxsd byok 保持运行。

本接入不代替客户端官方账号或商业授权。自选模型会以模型库中的名称加入 Devin 原生选择器。普通账号仍按 Devin 官方套餐登录；本产品只把已经登录的客户端模型请求改为由本机模型库回答。停用 Devin 无需修改 Cursor 的独立接管设置。
